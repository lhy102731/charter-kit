# Multi-Target Distribution and Codex Marketplace Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Separate the host-neutral Charter Kit core from target packaging, publish a self-contained Codex package through GitHub marketplace, and document command-line installation bilingually.

**Architecture:** Keep `portable/` and the root charter documents as the semantic source of truth. Add `targets/codex/` as the Codex adapter source and generate the committed, self-contained `plugins/charter-kit/` distribution from it. Add a repository marketplace manifest that points to `./plugins/charter-kit`; retain the old root plugin snapshot only as a generated migration compatibility layer.

**Tech Stack:** Markdown, JSON, YAML, Python 3 standard library, Codex plugin manifest/marketplace conventions, unittest.

**Spec:** `docs/superpowers/specs/2026-09-01-multi-target-distribution-design.md`

## Global Constraints

- `portable/` remains the only semantic source of truth.
- The Codex distribution is self-contained and never reads a sibling or parent core directory after installation.
- `plugins/charter-kit/` is the only new formal Codex/GitHub distribution path and uses `.codex-plugin/plugin.json` plus `./skills/`.
- Root `.codex-plugin/` and `skills/` are migration snapshots only; they are generated and validated, not hand-maintained.
- Core mirrors are compared byte-for-byte, including newline bytes.
- Build and validation are read-only with respect to global directories, network, credentials, and dependencies.
- No target adapter installs or bundles an external harness.
- Existing `charter/v1` semantics and package version `0.2.0` remain unchanged.
- README contains equivalent Chinese and English installation, update, safety, and contribution guidance with useful hyperlinks.
